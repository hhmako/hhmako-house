# 飞书应用接入

实时监听不是 webhook 发卡片能力。它需要一个企业自建应用通过长连接接收群消息事件。

## 1. 创建或复用企业自建应用

在飞书开放平台创建企业自建应用，并启用机器人能力。把机器人加入以下目标群：

- 抖音商城问题反馈吐槽群。
- 抖音商城 App（独立端）问题反馈群。
- 用于人工 @ 录入的设计群。
- 接收实时卡片的目标群。

群名只是说明，实际识别依赖 `chat_id`。

## 2. 权限

按飞书后台当前权限名称申请以下能力：

- 接收群聊中 @ 机器人消息或群消息事件。
- 读取应用所在群的消息。
- 获取消息中的图片/文件资源。
- 上传消息图片。
- 以机器人身份发送消息或卡片。
- 读取必要的用户基本信息（仅在业务确实需要时）。

权限名称可能随开放平台版本调整，以 `im.message.receive_v1` 和相关 API 页面列出的权限为准。

## 3. 事件订阅

1. 在“事件与回调”中选择“使用长连接接收事件”。
2. 添加事件 `im.message.receive_v1`。
3. 保存。
4. 创建并发布应用版本。
5. 确认管理员已审批新权限和新版本。

只在代码里启动 WebSocket、不在后台订阅事件，收不到任何消息。

## 4. 获取群 chat_id

可使用有权限的 `lark-cli`：

```bash
lark-cli im +chat-search --query "群名"
```

把结果写入本机 `config.local.json` 的 `realtimeGroups.sources`。不要提交真实 chat_id。

## 5. 启动长连接

```bash
npm run group:listen
```

启动日志应包含：

- `listener_starting`
- 配置的来源群名称
- 本地 state 文件位置

群内新消息会经过：

1. 授权群 / @ 机器人校验。
2. 同一发送人的相邻文字与图片合并。
3. 原始图片下载。
4. 体验问题规则闸门。
5. message_id 去重。
6. Base 写入，状态固定为 `待确认`。
7. 实时单条卡片发送。

未通过规则的候选只写入本机 `runtime/group-inbox/`，不会正式入库或发卡片。

## 6. 常驻运行

开发验证后使用：

```bash
npx pm2 start ops/ecosystem.config.cjs
npx pm2 save
```

应用 Secret、登录态和运行状态必须保留在部署机器，不得上传 GitHub。
